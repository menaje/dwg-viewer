# 화면 오차 기반 곡선 정밀화

## 선택

확대용 다중 LOD를 변환 시 미리 생성하지 않고, Scene Cache에 이미 보존된
곡선 원본을 확대가 멈춘 뒤 Web Worker에서 다시 세분화한다.

| 방식 | 캐시·첫 화면 | 확대 시 비용 | 판단 |
| --- | --- | --- | --- |
| 변환 시 다중 LOD | 모든 도면에서 캐시와 변환 시간이 증가 | 낮음 | 사용하지 않음 |
| 원본 지연 분석 | 첫 화면 변화 없음, 원본은 한 번만 보존 | 첫 4× 확대 때 Worker 읽기·계산 | 채택 |

도면 이동 중에는 기존 제한형 근사를 계속 사용한다. 정밀 결과는 요청한
카메라와 현재 카메라가 정확히 일치할 때만 활성화되므로, 이전 화면 결과가
이동한 화면에 나타나지 않는다.

## 오차 계약

- 최종 목표: 화면 편차 `0.5 px` 이하
- 곡선 세분화: 최대 `0.45 px`
- 배치 원점 기준 f32 위치 저장: 최대 `0.05 px`
- 원·호와 bulge는 sagitta 식으로 선분 수를 계산한다.
- ELLIPSE와 NURBS는 각 knot/사분 구간의 1/4, 1/2, 3/4 지점을 검사하며
  제한 깊이 안에서 재귀 분할한다.
- 한 객체는 완전한 정밀 결과가 만들어졌을 때만 기존 근사를 교체한다.
  잘못된 knot, weight, 법선, 퇴화 곡선이나 한도 초과 객체는 기존 제한형
  근사를 그대로 유지한다.

지원 원본은 ARC, CIRCLE, ELLIPSE, LWPOLYLINE·2D POLYLINE bulge,
비선형 NURBS SPLINE이다.

## 읽기와 메모리 상한

- 첫 화면에서는 곡선 원본 섹션을 읽지 않는다.
- 정밀화는 안정된 화면의 4× 확대부터 시작한다.
- 곡선 원본의 단일 범위 읽기: 최대 `512 KiB`
- Worker가 유지하는 곡선 원본: 최대 `64 MiB`
- 정밀 선 단일 GPU 배치: 최대 `512 KiB`
- 현재 화면의 정밀 곡선 GPU 합계: 최대 `32 MiB`
- 한 곡선: 최대 65,536 선분

한도에 걸린 객체는 교체 대상 핸들에 포함되지 않으므로 화면에서 사라지지
않는다.

## 블록과 렌더링

곡선 정점은 블록 정의마다 한 번만 만든다. 화면에 보이는 INSERT 인덱스만
배치에 연결하며 INSERT 개수만큼 정점을 복제하지 않는다.

기존 정점의 선종류 거리 값은 원래 `0` 이상이다. 교체 대상 정점은 같은
f32 값의 음수 영역에 가역적으로 표시하고 셰이더에서 원래 거리로 복원한다.
따라서 style 상위 비트를 사용하는 WIPEOUT 가림 순서, 색상, 선가중치,
단순·복합 선종류와 충돌하지 않는다. 이동 중이거나 카메라가 달라지면 이
표시를 무시해 즉시 기존 근사를 보여준다.

## 실제 도면 확인

`A2-013`에서 만든 Scene Cache v1.15로 확인한 결과:

- 곡선 원본 36,082,784 bytes, 73회 읽기
- 최대 읽기 524,288 bytes
- ARC 22,539, CIRCLE 2,795, ELLIPSE 1,328, POLYLINE 11,596,
  SPLINE 12,330
- 선택 화면에서 84개 곡선, 416개 선분, GPU 29,952 bytes
- 같은 화면 재계산은 별도 Worker에서 약 150–200 ms

UI 스레드는 확대·이동 중 기존 GPU 선만 그리므로 이 계산 시간 때문에
포인터 이동이 멈추지 않는다.
